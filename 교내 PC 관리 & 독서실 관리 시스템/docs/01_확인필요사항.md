# 확인 필요 사항

설계안 검토에서 나온 항목입니다. 원본 설계안은 수정하지 않고 보존했습니다.

## 1. 설계안 오타 의심

원본 44번째 줄:

> 센서가 12초 반짝 true … 최소 1530초 이상 연속으로 사람이 감지될 때만

`~`가 빠진 표기로 보입니다. 의도가 "1~2초 반짝 무시, 15~30초 이상 연속 감지 시 복귀 인정"인지 확인이 필요합니다. 현재 문구대로면 25분 넘게 연속 감지되어야 복귀로 인정됩니다.
- [ ] 정확한 값 확정: 노이즈 무시 시간 ___초 / 복귀 인정 연속 감지 시간 ___초

## 2. 기술 결정

- [ ] 서버 언어/프레임워크 (노트북 쪽이 C#이라 ASP.NET이면 모델 공유가 쉬움)
- [ ] 서버 DB (SQLite 등 로컬 DB 권장)

## 4. 설계상 위험 요소

- **"0.1초 만에 재실행"**: 서비스 복구와 Watchdog은 보통 수백 ms~수 초가 걸립니다. 목표 수치를 현실적으로 수정해야 합니다.
- **TickCount64 시간 방어**: 절전/최대 절전 동작과 서버 재동기화 시점을 실제 테스트로 확인해야 합니다.
- **삭제 방지와 제거 절차**: 프로그램 목록 숨김, ACL 잠금을 적용하면 학생이 졸업/전학 시 직접 지울 수 없습니다. 교사용 해제 절차와 원격 제거 기능을 먼저 만들어야 하고, 테스트 PC에서도 필요합니다.
- **개인정보 동의**: 개인 노트북의 프로세스/사이트 감시 범위를 고지하고 동의서를 받는 절차가 필요합니다.
- **백신 오탐**: 자기 보호/숨김 기법은 악성코드로 오탐될 수 있습니다. 코드 서명과 학교 PC 예외 등록 방안이 필요합니다.
- **센서 간섭**: 책상 상판 투과 방식은 재질과 옆자리 간섭 영향이 큽니다. 설치 방식은 현장 테스트 후 결정합니다(설계안에도 명시).
