# BNO055 방위각 센서 정리

로봇의 방향(yaw)을 MPU9250 자이로 적분 방식에서 **BNO055 (DFRobot Gravity)** 로 교체한 내용을 정리한 문서입니다.
구현 파일: [arduino_33ble/arduino_33ble.ino](arduino_33ble/arduino_33ble.ino)

> 컴파일과 보드 테스트는 아직 진행하지 않았습니다. 특히 플래시 저장(`mbed::FlashIAP`)은 보드에서 확인이 필요합니다.

## 1. 왜 바꿨나

| | MPU9250 (이전) | BNO055 (현재) |
|---|---|---|
| yaw 계산 | 자이로 Z축을 적분 | NDOF 모드, 지자기+자이로+가속도 융합 |
| 기준 | 켜진 순간이 0° | 자북 기준 0~360° (영점 설정으로 시작 방향을 0°로 변경 가능) |
| 문제 | 전원을 켤 때마다 기준이 바뀌고 시간이 지나면 드리프트 | 지자기로 드리프트 보정 |

## 2. 데이터 흐름

```
BNO055 --(I2C)--> Nano 33 BLE --(Serial1, "YAW:xxx.x")--> Mega
```

- 나노가 20Hz(50ms)로 yaw를 계산해서 Mega로 `YAW:` 형식으로 보냅니다. 이 형식은 이전과 같아서 Mega 코드는 바꾸지 않았습니다.
- 센서 연결에 실패하면 YAW를 보내지 않고, Mega의 1초 수신 두절 감지가 동작합니다.
- 방위각은 시계방향으로 증가합니다. 이전 yaw 규약과 같습니다.

## 3. 설치 방법

DFRobot Gravity BNO055 보드의 축 표시는 이렇습니다.

- **X축: 커넥터(+, -, C, D) 쪽**
- Y축: 보드 위쪽, Z축: 부품면에서 나오는 방향

설치 조건:

1. **커넥터 쪽이 로봇 정면**을 향하게 합니다. (X가 앞, Y가 왼쪽, Z가 위)
2. 부품면이 위를 보게 **수평**으로 고정합니다.
3. 모터, 모터 드라이버, 배터리, 큰 전류가 흐르는 전선과 가능한 한 떨어뜨립니다.
4. 철판이나 나사 위에 바로 붙이지 말고 플라스틱 스페이서로 띄웁니다.
5. 배선: `C`는 SCL, `D`는 SDA, I2C 주소는 0x28입니다. 안 되면 0x29로 자동 재시도합니다.

설치 확인: 로봇을 시계방향으로 90° 돌렸을 때 yaw가 약 +90° 늘어나야 합니다. 반대로 줄면 축이 반대로 설치된 것입니다.

## 4. 라이브러리

Arduino 라이브러리 매니저에서 설치합니다.

- Adafruit BNO055
- Adafruit Unified Sensor

주의: 함수 이름은 `setExtCrystal`이 아니라 **`setExtCrystalUse`** 입니다.
DFRobot 보드에 외부 크리스탈이 없다면 이 설정이 측정을 불안정하게 만들 수 있습니다. YAW가 튀면 `setExtCrystalUse(true)` 줄을 주석 처리해서 비교해 보세요.

## 5. 부팅 순서

1. BNO055를 연결합니다.
2. 플래시에 저장된 보정값이 있으면 **복원**합니다.
3. 지자기 보정이 끝날 때까지 대기합니다. (최대 60초, 0.5초마다 `Calib Sys/G/A/M` 출력)
4. `M:3`이 되고 로봇이 약 3초 정지해 있으면 그 방향을 **yaw 0°로 설정**합니다.
5. 보정이 처음이면 Sys, G, A, M이 모두 3이 되는 순간 **플래시에 자동 저장**합니다.
6. 이후 `YAW:`를 Mega로 계속 보냅니다.

대기 중에는 Mega로 YAW가 가지 않고 BLE도 시작되지 않습니다. 60초 안에 보정이 끝나지 않으면 경고 후 현재 방향으로 영점을 잡고 계속 진행합니다. (이 경우 방위가 부정확할 수 있습니다.)

## 6. 보정값 저장과 복원

nRF52840에는 EEPROM이 없어서 내장 플래시의 **맨 끝 섹터**에 저장합니다. 매직 값과 체크섬으로 깨진 데이터를 걸러냅니다.

| 상황 | 해야 할 일 |
|---|---|
| **처음 사용** (저장값 없음) | 부팅 후 센서를 8자로 움직여 모두 3이 되면 자동 저장 |
| **그 다음 부팅** | 저장값 복원. 센서를 살짝 움직여 `M:3`만 확정하면 됨 |
| **환경이 바뀌었을 때** (센서 위치, 모터, 배터리 배치, 설치 장소) | `CLEARCAL` 전송, 재부팅, 8자로 보정하면 자동 저장 |

저장한 지자기 보정값은 로봇의 자기 환경이 같을 때만 맞습니다. 환경이 바뀐 뒤에도 옛 값을 쓰면 방위가 틀어질 수 있습니다.

## 7. 명령어

시리얼 모니터(USB, 9600 baud, 줄바꿈 Newline)나 BLE로 보냅니다. **대문자로 정확히** 입력해야 합니다. 다른 문자열은 Mega로 전달됩니다.

| 명령 | 동작 | 사용 시점 |
|---|---|---|
| `YAWZERO` | 현재 방향을 yaw 0°로 다시 설정 | 보정 후 출발 방향에 놓았을 때 (**정지 상태에서만**) |
| `SAVECAL` | 현재 보정값을 플래시에 저장 (Sys, G, A, M이 모두 3일 때만) | 이미 저장값이 있는 상태에서 재보정한 뒤 수동으로 덮어쓸 때 |
| `CLEARCAL` | 저장된 보정값 삭제 | 환경이 바뀌어 재보정이 필요할 때 |

이 명령들은 `setup()`이 끝난 뒤의 `loop()`에서만 받습니다. 부팅 직후 보정 대기 중에는 받지 않습니다.
`YAWZERO`를 주행 중에 보내면 yaw가 갑자기 바뀌어 헤딩 유지와 오도메트리가 어긋납니다.

## 8. 시리얼 모니터 출력 예시

```
[IMU] 지자기 보정 대기 중... 로봇을 8자로 움직여 주세요.
[IMU] Calib Sys:1 G:3 A:2 M:0
...
[IMU] 지자기 보정 완료! 출발 방향에 놓고 가만히 두세요.
[CAL] 보정값 플래시 저장 완료
[IMU] 영점 설정 완료. 기준 방위각: 50.0
[IMU] YAW: 0.3 [Calib Sys:3 G:3 A:3 M:3]
```

## 9. 조정할 수 있는 값

`waitCalibrationAndZero()` 맨 위 상수입니다.

| 상수 | 기본값 | 의미 |
|---|---|---|
| `CALIB_TIMEOUT_MS` | 60000 | 보정 대기 최대 시간 |
| `STILL_HOLD_MS` | 3000 | 영점을 잡기 전에 정지해 있어야 하는 시간 |
| `STILL_GYRO_RAD_S` | 0.05 | 이 값(약 3°/s)보다 작으면 정지로 판단 |

## 10. 알려진 제한과 확인할 점

- 실내에서는 철골이나 모터 때문에 지자기가 왜곡됩니다. 영점 방식(시작 방향이 0°)이라 맵과 맞추기는 쉽지만, 방향이 크게 바뀌는 구간에서는 오차가 날 수 있습니다.
- 플래시 저장 위치는 스케치 영역과 겹치지 않는다고 가정했습니다. 저장한 뒤에도 스케치가 정상으로 부팅하는지 확인하세요.
- 컴파일 오류가 나면 `FlashIAP` 관련 줄(`mbed.h`, `flashIap.*`)이 가장 먼저 의심됩니다.
- PC 프로그램에서 `YAWZERO`, `SAVECAL`, `CLEARCAL`을 보내는 버튼은 만들지 않았습니다. 지금은 시리얼 모니터에서 보내야 합니다.
- Mega의 `setup()`에 있는 `yaw = 0` 초기화는 그대로입니다. 첫 `YAW:` 패킷이 오면 덮어씁니다.
